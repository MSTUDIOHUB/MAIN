# Tasks

使用方式：
- 只保留真正可执行、可勾选、可验证的离散任务。
- 每个任务都应足够小，完成后能明确更新为 `[x]`。
- 如果任务来自某个 requirement，可在行尾标注 `→ 对应需求：REQ-xxx`。
- 如果当前是数据分析 / 报表 / 研究类 Plan，任务应优先拆成查询、校验、汇总、出报告、复核、自动化实现等步骤，不要默认写成工程开发任务。

## 执行约定
- 执行阶段以本文件 checkbox 为事实来源。
- 完成一个任务后，先同步更新本文件，再继续下一项。
- 所有任务都为 `[x]` 前，不要宣告任务完成。

## 任务列表
- [ ] 梳理并补齐本次实施所需上下文 → 对应需求：REQ-001
- [ ] 完成核心实现或文档产出 → 对应需求：REQ-002
- [ ] 补齐验证、回归或人工检查 → 对应需求：REQ-003
- [ ] 收尾：更新说明、总结结果、记录残留风险
- 数据分析类任务示例写法：
  - [ ] 明确数据源、时间范围、过滤条件与指标口径 → 对应需求：REQ-001
  - [ ] 执行关键查询 / 读取原始数据窗口并完成抽样核对 → 对应需求：REQ-001
  - [ ] 生成汇总表、关键结论与异常说明 → 对应需求：REQ-002
  - [ ] 输出 Markdown 报告 / 报表方案，并标注限制与建议 → 对应需求：REQ-003
  - [ ] 如已批准实现：补齐脚本、自动化或报表系统变更，并验证结果
