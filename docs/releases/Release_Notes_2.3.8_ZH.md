# MAIN 2.3.8 发布说明

本次构建日期：2026-11-05

版本跨度：2.3.7 → 2.3.8

MAIN 2.3.8 重点改进技能的发现、选择、调用与更新流程：本机 Agent 技能先由用户添加，GitHub 技能包由用户手动检查并确认更新，并统一了桌面端的启用开关。

## 主要更新

### 本机技能发现与来源管理

- “本机发现的技能”改为独立选择窗口，与“添加技能”并列，提供扫描、失败重试和空列表提示。
- 发现 Codex、Claude Code、Gemini 及其他来源的技能后，需先点击“添加到 MAIN”才能供 MAIN 使用；只记录技能路径，不复制内容，也不启动来源 Agent。
- 新增全局 Agent 来源开关。关闭来源后，其技能从后续执行和 `$` 菜单中排除；已添加设置会保留，重新开启后恢复，新发现的技能仍需手动添加。
- 已添加技能可设置为自动匹配、仅手动调用或停用，并支持项目与全局范围。项目技能保留项目边界；来源要求仅手动调用时，MAIN 尊重该限制。
- 来源开关仅控制本机 Agent 技能。独立导入的技能包继续通过技能主面板中的包启用开关管理。

### `$` 技能快捷菜单与帮助

- 在输入框输入 `$` 即可搜索当前已添加且启用的技能，包含仅手动调用的技能；未添加、停用或来源已关闭的本机技能不会出现在菜单中。
- 支持 `↑` / `↓` 选择、`Enter` / `Tab` 插入、`Esc` 关闭及鼠标选择，并处理输入法组合输入、工作区切换和异步加载期间的选择边界。
- 菜单展示技能来源，独立技能包显示具体包名，便于区分本机技能与导入的技能包。
- 输入框下方 `?` 帮助菜单补充中英文技能快捷键说明。

### GitHub 技能包手动检查与确认更新

- 有已验证 GitHub 来源的技能包会显示仓库、分支及“检查更新”按钮。手动检查下载并校验仓库快照，只生成候选版本，不直接替换已安装版本。
- 发现更新后展示新旧版本标识及技能数量，点击“更新”才应用。支持已是最新、检查失败重试、取消候选及重复版本冲突提示。
- 更新保留技能包的名称、描述、启用状态与调用方式。检查后若用户修改了该技能包，需重新检查，避免旧候选覆盖新设置。
- 更新供下次启动执行使用，正在运行的任务保留原版本。没有后台自动检查或自动更新；技能的“自动匹配”设置也不会触发包更新。
- 旧 ZIP 包没有可推断的 GitHub 来源。首次需要在编辑中填写仓库与分支，成功下载并保存后关联来源；仅修改输入字段不会改变已安装来源。

### 全局技能包与支持资源读取

- 通过通用 GitHub 或 ZIP 入口导入单个技能或整套技能，并保留 `references`、`scripts` 等支持文件，安装一次后可跨项目使用。
- 技能包使用完整内容身份与不可变缓存；相同内容复用安装，重复导入保留已有用户设置，后续更新不改写当前任务持有的旧内容。
- 技能说明及关联文本资源按需、分段读取，并遵守当前执行的上下文预算。资源读取限定在已注册技能包内，校验路径和内容版本，避免越界或混用不同版本。
- 技能说明及资源不会授予额外执行权限。读取脚本不等于执行脚本，命令、MCP 和 Unity Editor 操作仍经过各自的工具与授权流程。

### 桌面设置与兼容性修复

- “系统设置 → 关于”完整显示对应版本的 Markdown 更新说明，支持滚动阅读，并可打开该版本的发布页面；不再截断为前 520 个字符。
- 统一 GitHub Actions、本地发布与应用更新源的说明来源：已有版本归档时，发布页面、`release_notes.md` 和 `latest.json` 均使用同一份已编写的 Release Notes。
- 统一启用／停用设置为胶囊开关，覆盖技能、设置、知识库、图像工作流、工具自动审批及文件自动换行等入口；完善键盘操作、禁用状态、焦点和浅色、深色、纯黑主题样式。
- 移除专用的 Gemini CLI 扩展面板及 Gemini ZIP 导入流程。通用 GitHub／ZIP 技能包导入、本机 Gemini 技能来源及 Gemini 模型配置继续保留；MCP 在 MAIN 的 MCP 设置中单独配置。
- 修复已获当前执行准入的子 Agent 工具被工具发现过滤隐藏的问题，同时保留协作容量与执行阶段限制。
- 修复受信任命令中平台空设备重定向的兼容问题，普通文件路径仍遵守原有工作区与授权边界。

### 任务执行与验证修复

- 恢复自然语言提交时的语义预检，保证请求先识别意图，再进入对应执行流程；恢复会话和排队提交沿用同一入口。
- 修改已有文件前重新校验当前源码读取凭据，整文件覆盖同样需要完整的当前源码；新建与覆盖按实际文件状态区分，避免读取一个文件后修改另一个未读取的文件，或以“新建”覆盖旧文件。
- Plan 中显式填写的非法依赖和验证步骤索引会被拒绝并反馈原因，避免静默改写后误认为计划有效。
- 修复执行工具发现与恢复指引的一致性。重复读取或纠错次数只用于调整策略，任务依据实际执行、验证结果及无进展恢复期限收口。

`latest.json`、`*_updater_*` 与 `.sig` 用于应用内更新及完整性校验，手动安装只需下载上表中的 zip。Updater 签名与 Apple / Windows 的开发者身份签名用途不同。
