# MAIN 产品能力、工作流与本地智能体优势说明（网站展示版）

适用场景：
- 用于 `main.mstudiohub.com` 的产品介绍页、功能页、FAQ 或能力说明页
- 面向用户解释：这个桌面 AI 编程助手能做什么、受什么约束、哪些文件可读、界面上各个区域分别负责什么

---

## 1. 一句话介绍

MAIN 是一个本地优先的桌面 AI 智能体工作台：它不只负责聊天，还能在你的工程与本地资料里完成“理解项目 / 文档 / 数据 -> 规划方案 -> 审批执行 -> 展示 Diff / 终端 / 计划进度”的完整闭环。

---

## 2. 核心能力概览

### 2.1 三种工作模式

| 模式 | 用途 | 典型场景 |
|---|---|---|
| Chat | 分析、问答、澄清需求、头脑风暴 | 先理解问题、整理方案、解释代码 |
| Fast | 直接执行明确任务 | 小改动、直接修复、快速落地 |
| Plan | 复杂任务的 review-first 流程 | 多文件改动、重构、新功能、风险较高任务，或多阶段分析 / 报表 / 自动化方案 |

补充说明：

- Plan 不再只代表“代码工程计划”
- 当选择数据分析师 Persona 时，Plan 会被改写成“分析计划 / 报表计划 / 自动化分析计划”
- 也就是说：**保留 Plan，但让 Plan 的内容语义随角色切换**

### 2.2 角色与场景扩展

MAIN 不只适合代码开发，也适合资料理解与数据分析。当前比较重要的角色包括：

| 角色 | 更擅长的方向 |
|---|---|
| 系统架构师 | 复杂项目结构、模块边界、方案设计、Spec-First 工作流 |
| UI 交互设计师 | 页面结构、交互体验、视觉一致性 |
| 代码调试专家 | Bug 定位、根因分析、修复验证 |
| 数据分析师 | 表格分析、文档解读、总结报告、报表方案、分析计划 |

### 2.3 复杂任务闭环

当任务复杂时，MAIN 不会直接盲改，而是走更稳的流程：

1. 先理解用户最终目标与约束
2. 审批前先生成 `requirements.md` / `design.md` 或 `bugfix.md`
3. 允许用户先保存方案，再决定是否执行
4. 等待用户确认方案
5. 仅在确认后再生成 `tasks.md`
6. 按任务逐项执行，并同步勾选进度
7. 最终展示结果、Diff、验证信息与残留风险

这套流程的目标是减少“模型看起来在做事，但中途停掉”或“只给计划、不真正执行完”的问题。

### 2.4 截至 2026 年 4 月 21 日的重点更新

今天这一轮改动，主要把 MAIN 从“能用的桌面 Agent”继续推进到“更稳、更适合真实工作流的桌面 Agent”：

1. **Plan 流程更合理**
   - 先生成需求 / 设计文档
   - 等待用户确认
   - 确认后才生成 `tasks.md`
   - 更符合“先方案后执行”的真实协作方式
2. **方案可以导出保存**
   - Plan 面板新增可保存当前文档的能力
   - 适合“只想保留方案、不想立刻执行”的用户
3. **任务进度改成基于真实 `tasks.md` 与执行证据**
   - 不再因为“成功写过一次文件”就误判任务推进
   - 执行面板与任务状态刷新更贴近真实执行过程
4. **Top Island 与右侧 Plan 面板联动增强**
   - 批准后再进入执行
   - 执行中持续展示任务数、完成数、当前阶段与审批状态
   - 任务完成后更容易看到状态已刷新
5. **代码修改摘要与 Diff 查看链路更完整**
   - 模型修改文件后，聊天区可显示变更摘要
   - 点击后可进入 Diff 面板查看精确改动
   - 重载后仍可恢复最近的 Diff 查看状态
6. **执行中断后的恢复能力更强**
   - 运行态快照会被持久化
   - 页面重载、自修改应用或执行中断后，更容易从剩余任务继续恢复
7. **新增数据分析师 Persona 与分析工作流**
   - 支持更自然地做表格分析、资料解读、Markdown 报告输出
   - 读表失败时优先自动走只读回退，不把普通分析任务误导成工程实施
8. **数据分析场景下的 Plan 被重写为“分析计划”**
   - 不禁用 Plan
   - 但会把 `requirements.md / design.md / tasks.md` 改写成分析目标、分析方法、查询与报告步骤，而不是代码工程计划
9. **回归测试覆盖更完整**
   - 已补充“生成计划 -> 保存方案 -> 批准执行 -> 完成收尾”等关键流的自动化验证思路
   - 降低后续改动把工作流悄悄改坏的风险
10. **运行中状态展示更稳定**
   - 执行过程中的状态条与计时器展示更可靠
   - 用户更容易判断 Agent 是否仍在持续工作，而不是误以为已经卡住

## 3. 内置约束系统

MAIN 的约束不是单点提示词，而是多层协作：

### 3.1 全局行为总纲

- `AGENT.md`
- 用来约束整体行为方向，例如：
  - 先识别最终目标，而不是机械照字面执行
  - 区分“只要方案 / 先方案后执行 / 直接执行”
  - 优先最小实现，避免过度设计
  - 坚持外科手术式修改
  - 最终回复必须说明验证结果与残留风险

### 3.2 项目级背景与约定

- `.MAIN/steering/*.md`
- 用来提供项目背景、技术栈、结构组织、约定与边界
- 例如：
  - 产品定位
  - 技术约束
  - 目录结构
  - Plan 模式下的进度真相来源
  - 改动范围与验证要求

### 3.3 针对特定模块的规则

- `.MAIN/rules/*.md`
- 用于声明某些关键文件或关键流程必须满足的不变量
- 例如：
  - `tasks.md` 是 Plan 执行进度的单一事实来源
  - 不能因为“写了一个文件”就误判为“完成了一个任务”
  - 执行阶段若仍有未完成任务，不能静默收尾

### 3.4 模板驱动

- `.MAIN/templates/intent/*.md`
- `.MAIN/templates/plan/*.md`
- `.MAIN/templates/report/*.md`
- 用来稳定输出结构，减少模型自由发挥导致的偏差
- 例如：
  - 意图分析模板
  - 需求模板
  - 设计模板
  - 任务模板
  - Bugfix 模板
  - 数据总结模板
  - 数据分析报告模板

### 3.5 生命周期 Hook

- `.MAIN/hooks.json`
- 目前主要用于执行期护栏
- 例如：
  - 在 Plan 模式下，若 `tasks.md` 仍有未完成项，提醒模型不要提前宣告结束
  - 让“完成检查”不只是口头判断，而是结合真实任务文件与执行证据

### 3.6 数据分析专用规则层

- `.MAIN/rules/data_analysis_workflow.md`
- 用来约束数据分析师 Persona 下的行为重点，例如：
  - 优先使用 `analyze_tabular_document` / `query_tabular_document` / `read_document`
  - 只读失败时自动回退，不先向用户申请“降级批准”
  - 在 Plan 模式下，把规格文件写成分析计划，而不是工程开发计划

### 3.7 用户自定义 Skill

Skill 面板支持三类扩展：

| 类型 | 作用 |
|---|---|
| Instruction Skill | 作为附加行为规则注入上下文 |
| Tool Skill | 暴露成模型可调用的工具 |
| Package Skill | 导入多文件协议包，形成完整工作流扩展 |

说明：
- Skill 是增强层，不应替代项目内置规则
- 对于稳定需要生效的行为，更推荐内置到 `AGENT.md` / `.MAIN/steering` / `.MAIN/rules`

## 4. 可以读取哪些内容

需要区分两件事：

1. **Agent 可读取哪些文件内容**
2. **右侧界面可直接预览哪些文件**

这两者并不完全相同。

### 4.1 Agent 可直接读取的文本 / 代码文件

通过 `read_file`，可读取适合按文本处理的文件内容，例如：

- 源码：`.ts` `.tsx` `.js` `.jsx` `.rs` `.py` `.go` `.java` `.kt` `.c` `.cpp` `.h` `.hpp` 等
- 配置：`.json` `.jsonc` `.yaml` `.yml` `.toml` `.ini` `.env` `.xml`
- 文档：`.md` `.txt` `.rst`
- 以及其他纯文本文件

特点：
- 返回完整文本内容
- 更适合源码、配置、Markdown、日志
- 如果目标文件被判定为二进制内容，会拒绝按文本读取

### 4.2 Agent 可读取的结构化文档

通过 `read_document`，可读取以下文档：

| 类型 | 扩展名 |
|---|---|
| PDF | `.pdf` |
| Word | `.docx` |
| Excel | `.xlsx` `.xls` |
| 表格文本 | `.csv` `.tsv` |
| 纯文本文档 | `.txt` `.md` `.markdown` `.rst` |

返回内容不只是纯文本，还可能包含结构化元数据，例如：

- PDF 页码
- Excel sheet 名称
- 单元格范围
- 段落 / 表格信息
- 文档标题

适用场景：
- 读取 PRD、方案说明、需求文档、表格资料、项目资料库

边界说明：
- 如果 PDF 本身是图片扫描版、没有文本层，提取结果可能有限，必要时需要 OCR

### 4.3 Agent 可先索引再决定读什么

通过 `index_workspace_documents`，可先扫描目录中的资料文件，再决定深入读取哪些文档。

支持索引的扩展名包括：

- `.pdf`
- `.docx`
- `.xlsx`
- `.xls`
- `.csv`
- `.tsv`
- `.txt`
- `.md`
- `.markdown`
- `.rst`

适用场景：
- 项目里资料很多，不想一上来就逐个读文件
- 先获得“有哪些文档 + 每个文档的预览摘要”

### 4.4 Agent 可读取的结构信息

除了直接读文件内容，MAIN 还支持读“结构”：

| 能力 | 说明 |
|---|---|
| `get_project_skeleton` | 快速读取项目目录骨架，适合全局理解工程 |
| `get_file_outline` | 提取 C# 文件的类型定义与 public/protected 成员签名 |
| `list_directory` | 扫描目录 |
| `glob_search` | 按模式搜索文件 |
| `grep_search` | 在文件内快速搜索文本 |

这意味着它不只是“打开文件”，而是能先从工程结构层理解项目。

### 4.5 图片输入

MAIN 还支持用户直接粘贴或拖拽图片进入对话：

- 剪贴板粘贴图片
- 拖拽图片到输入区
- 自动压缩与缩放，便于多模态模型处理

适用场景：
- UI 截图
- 报错截图
- 原型图
- 设计参考图

## 5. 右侧界面可以预览哪些文件

右侧文件查看面板当前按 4 类显示：

| 类别 | 说明 |
|---|---|
| Markdown | 渲染为富文本 Markdown 视图 |
| Image | 显示图片预览 |
| Code / Text | 语法高亮代码视图 |
| Binary | 显示“二进制文件，无法预览” |

### 5.1 直接图片预览

支持图片扩展名：

- `.png`
- `.jpg`
- `.jpeg`
- `.gif`
- `.webp`
- `.bmp`
- `.ico`
- `.avif`

### 5.2 直接 Markdown 预览

主要支持：

- `.md`

### 5.3 二进制占位显示

以下类型在右侧文件查看中默认视为二进制，不直接渲染：

- 文档：`.pdf` `.doc` `.docx` `.xls` `.xlsx` `.ppt` `.pptx`
- 压缩包：`.zip` `.tar` `.gz` `.rar` `.7z`
- 媒体：`.mp3` `.mp4` `.avi` `.mov` `.mkv` `.wav` `.webm`
- 字体 / 编译产物 / 二进制文件等

重要说明：
- **右侧无法直接预览** 不代表 **Agent 无法读取**
- 例如 PDF / DOCX / XLSX 虽然界面里按二进制显示，但 Agent 仍可通过 `read_document` 读取其内容

## 6. 灵动岛（Top Island）设计说明

Top Island 是 MAIN 的核心交互之一，它不是装饰，而是“当前任务状态的即时中控条”。

### 6.1 它负责显示什么

- 当前查看的任务标题
- 当前回合状态
- 任务数与完成数
- 是否有待审批计划
- 是否有待审批变更

### 6.2 它能做什么

- 鼠标悬停展开
- 一键锁定展开 / 解除锁定
- 展示当前计划任务进度条
- 展示当前阶段任务列表
- 当 `tasks.md` 实际更新后，优先刷新对应的计划任务状态
- 直接跳转到 Plan 面板
- 直接跳转到 Diff 面板
- 在有待审批变更时，直接在岛内执行：
  - 单次批准
  - 当前会话全部允许
  - 拒绝
- 在有待审批计划时，直接开始执行

### 6.3 为什么它重要

对于 Agent 类产品，真正决定体验的不是“会不会输出很多字”，而是：

- 用户能否一眼看懂现在处于什么阶段
- 是否正在执行
- 还剩多少任务
- 是否需要用户批准
- 出现变更时能否快速跳到 Diff

Top Island 的作用，就是把这些高频状态聚合到最前面，降低用户在聊天流、计划面板、Diff 面板之间来回切换的成本。

## 7. 右侧工作区设计说明

右侧工作区是 MAIN 的第二个核心设计，它负责把“执行过程”拆成可见的几个维度：

### 7.1 Plan 面板

负责展示：

- 当前计划文档
- 当前阶段
- 任务进度
- 审批按钮
- 恢复执行按钮
- 计划导出 / 保存按钮（适合“只保留方案，不立即执行”）

复杂任务里，用户不必回聊天记录里翻找方案，右侧会持续保留规划文档与最新任务状态。

### 7.2 Diff 面板

负责展示：

- 待审批变更
- 最近一次文件改动
- 增删行统计
- 精确 Diff 内容
- 聊天区里的变更摘要可直接跳转到这里
- 页面重载后仍可尽量恢复最近一次查看的 Diff

用户可以从聊天摘要、ActionCard 或 Top Island 进入 Diff 视图。

### 7.3 Terminal 面板

负责展示：

- 集成终端输出
- 命令执行结果
- Agent 对命令执行后的验证链路

### 7.4 File Viewer 面板

负责展示：

- Markdown 文档
- 图片
- 代码文本
- 二进制占位提示

## 8. 用户可感知的安全与稳定性设计

### 8.1 工作区范围安全

MAIN 的文件操作默认受工作区范围约束：

- 读取和写入默认基于当前工作区
- 避免越界访问任意路径
- 规划文档与普通导出路径分开处理

### 8.2 写操作默认需要审查

对于普通写操作，例如：

- `write_file`
- `replace_in_file`
- `execute_command`

系统会结合审批机制与 UI 审查流处理，避免模型静默改动。

### 8.3 复杂任务先规划再执行

Plan 模式下强调：

- 先生成方案
- 再等待用户确认
- 再拆解任务
- 再执行

这比“边想边改”更适合多文件和高风险任务。

### 8.4 `tasks.md` 作为执行真相来源

MAIN 强调：

- 计划完成状态不能只靠模型口头声明
- 任务是否真正完成，以 `tasks.md` 中的 checkbox 为准
- 完成检查 Hook 会在必要时提醒模型不要提前收尾

### 8.5 执行中断后的恢复能力

MAIN 现在会尽量保留当前运行态快照，包括：

- 当前回合与任务流
- Plan 文档与任务状态
- Diff 查看状态
- 已批准但尚未完成的执行上下文

这让它更适合以下情况：

- 用户中途刷新或重开窗口
- Agent 在修改自身界面或行为后导致页面重载
- 用户暂时离开，回来后继续剩余任务

## 11. 边界说明（官网建议保留）

为了避免过度承诺，官网建议同时说明以下边界：

- PDF 若为纯图片扫描件，文本提取可能有限
- `get_file_outline` 目前主要面向 C# 文件
- 某些文件类型可被 Agent 读取，但不一定能在右侧直接可视化预览
- Skill 适合作为增强层，不应替代项目内置规则
- 复杂任务的稳定性高度依赖工作区规则、模板与任务拆解质量

---

## 12. 推荐结论

如果用一句话总结 MAIN 当前最值得展示的能力，不是“它会不会写代码”，而是：

**它把本地 AI 编程从“一个会说话的模型”，变成了“一个有计划、有审批、有证据、有状态面板的可控执行系统”。**

## 13. 当前本地模型智能体软件的特点与好处（建议放在官网后段重点展示）

如果从“本地模型 Agent 软件”这个品类来看，MAIN 当前有几个很适合对外展示的特点：

### 13.1 特点

1. **本地优先**
   - 更适合私有代码、内部文档、敏感表格、离线或弱联网场景
2. **不是纯聊天，而是可执行工作流**
   - 支持 Chat / Fast / Plan 三种模式
   - 复杂任务有审批与任务链路
3. **过程可见**
   - Top Island、Plan、Diff、Terminal、File Viewer 共同组成状态面板
4. **不只懂代码，也能懂文档和数据**
   - 支持源码、Markdown、PDF、DOCX、XLSX、CSV、TSV、图片输入
5. **可约束、可定制**
   - 支持 `AGENT.md`、Steering、Rules、Templates、Hooks、Skills、MCP
6. **可恢复**
   - 执行中断、页面重载、自修改应用后，仍能尽量恢复上下文与进度

### 13.2 对用户的直接好处

| 特点 | 用户得到的好处 |
|---|---|
| 本地优先 | 数据更容易留在本机，隐私风险更低，适合企业内网和私有项目 |
| 审批式执行 | 降低误改风险，复杂任务更可控 |
| 任务真相来源 | “完成”不再只靠模型口头声明，更容易真正落地 |
| 多面板可见性 | 用户不用在长聊天记录里盲找状态，协作与复核效率更高 |
| 文档 / 表格 / 图片理解 | 不再局限于代码助手，更适合真实工作流里的资料型任务 |
| 方案可保存 | 即使暂不执行，也能把方案本身作为交付物留下 |
| 可恢复执行 | 更适合长任务、复杂任务、跨会话任务，不容易因为中断而从头再来 |
| 本地模型接入 | 更容易控制成本、延迟与模型选择，适合持续迭代自己的 Agent 能力 |

### 13.3 网站上可以用的一句总结

**MAIN 的价值不只是“让本地模型会写代码”，而是让本地模型真正变成一个有计划、有审批、有证据、有状态面板、还能理解文档与数据的桌面智能体。**
