# MAIN 工作区隐藏目录的设计取舍

2026-10-23。本文是设计分析，没有实施目录迁移、删除或权限策略变更。正在进行的修复和真实模型验证使用原有存储布局。

## 判断

项目内保留可选的 `.MAIN` 配置目录合理；仅添加工作区、开始普通对话就默认创建目录，不适合作为默认行为。应根据“谁拥有、是否需要共享、能否重建、是否含个人数据”决定位置。

源码实际使用 `.MAIN`。当前代码有项目规则、计划文档、索引、部分记忆与 trace 的落盘路径，但这些代码入口不全属于现行 TS 生产链，不能据此断言它们每次对话都会执行。权威 Session 与 canonical checkpoint 已经存放在应用数据目录 `sessions/session-store.sqlite3`，恢复对话并不要求项目中存在 `.MAIN`。

可核对：`src-tauri/src/indexer/mod.rs:87`、`src-tauri/src/memory/mod.rs:49`、`src-tauri/src/harness/tracing.rs:297`、`src-tauri/src/lib.rs:4810`、`docs/SESSION_PERSISTENCE.md`。

一个确定存在的“读取即创建”入口是 `knowledge_list_bases → knowledge_app_data_dir → create_dir_all(.MAIN)`；当前知识库组件只在打开时列举知识库，因此尚不能把它认定为用户所述“每次开始对话”的唯一触发源。后续实施前应使用文件创建日志定位真实触发栈。

## 其他 Agent 的做法

采用项目配置加用户存储的混合方式，有明确的官方实例：

- Claude Code 的共享项目配置是 `.claude/settings.json`，个人配置可位于 `~/.claude/settings.json`；个人项目覆盖另有 local 配置。自动记忆默认位于用户目录 `~/.claude/projects/<project>/memory/`。见[配置文档](https://code.claude.com/docs/en/settings)和[记忆文档](https://code.claude.com/docs/en/memory)。
- Gemini CLI 支持 `.gemini/settings.json` 项目配置，对话历史放在 `~/.gemini/tmp/<project_hash>/chats/`。见[配置文档](https://geminicli.com/docs/reference/configuration/)和[会话文档](https://geminicli.com/docs/cli/session-management/)。

这些实例支持分层存放的选择，并不意味着所有 Agent 都采用相同目录结构，或完全不写项目目录。

## 对 MAIN 的建议

| 数据 | 默认位置与行为 |
| --- | --- |
| 团队规则、项目工作流、共同维护的说明 | 项目内，用户启用时创建，可提交版本控制 |
| 对话、canonical ledger、checkpoint、审批事实、个人记忆 | 应用数据目录，按工作区、用户与 Session 隔离 |
| 可重建索引、缓存、调试日志、临时验证截图 | 应用缓存或诊断目录，设容量、保留期与清理入口 |
| 用户需要交付或共同维护的计划、报告、截图 | 明确的项目产物路径；必要时导出 |
| 凭证与密钥 | 系统凭证库或受保护的用户配置，不放入项目目录 |

项目内存储便于随项目移动、版本审阅与团队共享，也减少位置映射。但会带来未跟踪文件噪声、分支/合并冲突、云同步冲突、磁盘增长及隐私内容被误提交的风险。隐藏目录不自动被 Git 忽略，也不提供权限隔离。

应用目录让普通问答不污染工作树，对只读项目更友好，并便于统一做隐私、容量和清理管理。其代价是项目移动、更名、跨机器复制后需要重新关联，备份与导出也必须由应用提供。

推荐默认行为：

1. 添加工作区和普通对话不创建 `.MAIN`，目录列举遇到不存在应返回空。
2. 第一次启用项目共享设置或写入明确产物时才创建对应目录。
3. 应用维护工作区 ID 与规范路径的注册映射；项目移动可显式重新关联。不能只凭相同仓库远程地址，把不同克隆或 worktree 的会话和权限合并。
4. 为缓存提供清理，为 Session 提供导出、备份和删除；删除缓存不应删除任务记录。
5. 项目内配置与用户授权分开。复制项目、模型写入规则文件、读取旧审批记录都不能自动授予新的执行权限。恢复仍核对精确 owner、资源范围与有效期。
6. 若保留项目内运行数据，单独隔离并忽略该子目录；不应一概忽略整个 `.MAIN`，否则团队规则也无法共同维护。

## 迁移约束

迁移应复制、校验、切换读写所有权，并保留回退依据。canonical ledger 继续只有一个事实源；不让新旧位置长期双写。旧计划需保留路径/摘要/审批身份关联，尚未完成的 Run 不得因搬迁重放副作用。普通文件或缓存迁移成功也不能恢复旧会话的自动审批权限。

验收应覆盖空目录、只读工作区、已有 `.MAIN`、项目更名、两个克隆、多个 worktree、会话冷恢复、迁移中断、缓存清理及授权失效。创建触发源应先由实际日志确认，而不是根据目录名猜测。
