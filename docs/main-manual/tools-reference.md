# 工具参考

MAIN 的工具让 Agent 能够观察项目、修改文件、执行命令、检索资料、验证页面并调用外部服务。

<!-- screenshot: docs/main-manual/assets/tools-reference-blocks.png -->

## 适用场景

- 想知道 MAIN 能自动做什么。
- 想理解哪些工具需要审批。
- 排查某个工具失败或没有出现的原因。

## 前置条件

- 已配置模型。
- 需要项目文件时已打开工作区。
- 需要 MCP 工具时已扫描服务器。

## 内置工具

只读工具包括列目录、读文件、读取文档、分析表格、查询表格、索引工作区文档、glob 搜索、grep 搜索、项目骨架、文件 outline、终端日志读取和知识库检索。

写入工具包括完整写文件和局部替换文件。它们会触发审批和 Diff 审查。

命令工具包括一次性命令、交互式终端命令、向 PTY 发送输入、读取终端状态和清空终端捕获缓冲。

浏览器验证工具用于检查本地页面、DOM、控制台和交互状态。

Git 工具用于读取状态、列出改动、查看 Diff、提交、推送和创建分支。

## 扩展工具

技能工具来自 Skills 面板。提示词技能主要影响行为，工具型技能需要实际执行端支持。

MCP 工具来自已配置并扫描成功的 MCP 服务器。MAIN 会在任务开始时把可用 MCP 工具并入工具集合。

知识库工具来自知识库索引，用于搜索片段和读取摘录。

## 审批规则

只读工具通常自动执行。写文件、替换文件和运行命令通常需要审批。高风险 MCP 工具是否安全取决于服务器能力，建议保留人工审查。

## 步骤

1. 发送任务时说明需要 MAIN 观察、修改还是验证。
2. 查看工具块确认 MAIN 使用了哪些工具。
3. 只读工具失败时，检查路径、工作区或资料来源。
4. 写入或命令工具出现时，先审查审批卡片。
5. MCP 工具失败时，回到 MCP 设置测试连接并重新扫描。
6. 任务完成后，要求 MAIN 总结工具证据。

## 结果确认

- 工具块显示工具名、目标、状态和结果摘要。
- 文件变更可以在 Diff 中查看。
- 命令结果应包含输出或退出状态。
- MCP 失败时会显示连接或工具调用错误。

## 常见问题

**为什么模型说不能访问文件？**  
可能是模型工具协议兼容问题。MAIN 通常会提示使用 XML 工具调用或切换工具协议。

**为什么 MCP 工具没有出现？**  
确认 MCP 服务器启用、测试通过并完成扫描工具。

**工具输出被截断怎么办？**  
要求 MAIN 针对关键路径重新读取更小范围，或让它总结日志尾部。
