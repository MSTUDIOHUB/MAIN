# 计划

输入 `/计划` 和你的需求，MAIN 会先调查可查的事实，再通过 capsule 请你决定目的、范围和有价值的方法取舍。支持单选、多选和补充文字；推荐选项不会自动替你提交。

## 使用步骤

1. 描述目标、限制和你希望看到的结果。项目任务可先打开工作区，普通聊天也能制定计划。
2. 回答 capsule 中的问题。重大取舍未确定时，MAIN 会继续询问；访谈中的回答只提供信息，不授权执行。
3. 访谈完成后，MAIN 保存包含目标、用户决定、方案、步骤、验收和风险的文档。
4. 点击聊天中的“查看文档”读取已保存版本。仅形成方案的任务到此完成。
5. 如果选择实施计划，另行审阅并批准执行，再查看 Diff、任务进度和实际验证结果。

## 保存与恢复

项目文档按计划独立保存在 `.MAIN/plans/<documentId>/rev-<n>.md`；普通聊天文档保存在 MAIN 应用数据目录的对应会话中。不同会话不会覆盖同一个固定文件。

保存失败时不会显示完成或开放执行审批。新版本需要重新审阅，旧审批不授予新版本执行权。取消或尚未完成的访谈不会宣称文档已经保存。

实施方案已有正文，但验证方式或计划结构尚未完整时，MAIN 会先保存“草稿 · 待补全验证”，列出需要补充的内容。本轮以部分完成结束，不会为了同一缺口反复重写整份方案，也不会开放批准执行。

点击“补全验证”会创建新的计划轮次，读取原稿的准确版本并保留原始目标和已确认选择。补全后的文档独立保存；验证完整后才进入执行审批。原稿被移动、修改，或当前会话已切换时，旧入口不能继续提交。

## 项目规则

输入 `/规则` 可调查项目并起草根 `AGENTS.md`。先确认关键约束，再编辑草稿和审阅差异，点击保存后才写入。`/init` 是隐藏兼容别名，不再刷新目录事实快照。人工规则会在草稿和差异中保留，文件在审阅期间变化会阻止旧稿覆盖。
