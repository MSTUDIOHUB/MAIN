# 终端与工具

MAIN 通过工具连接项目文件、终端、文档、表格、浏览器验证和外部 MCP 服务，让任务结果可观察、可验证。

## 适用场景

- 让 MAIN 搜索和读取项目文件。
- 运行测试、构建、脚本或开发服务器。
- 分析 PDF、DOCX、CSV、XLSX 等资料。
- 验证本地网页或 UI 状态。

## 前置条件

- 已打开工作区。
- 需要运行命令时，确认项目依赖已安装。
- 需要浏览器验证时，确认目标页面可以本地访问。

## 工具类型

文件工具可以列目录、读文件、搜索文件、按 glob 找文件、提取项目骨架。

文档和表格工具可以读取文档、总结表格、查询大型表格数据。

终端工具可以运行一次性命令，也可以驱动长时间运行的交互式 PTY。一次性命令适合会自行退出的测试、构建与脚本；dev server、watch 或需要持续输入的进程应使用 PTY。

浏览器验证工具适合检查 DOM、控制台、页面状态和本地 Web 应用行为。

## 步骤

1. 在任务中明确需要验证的方式，例如“请运行测试”或“请打开本地页面检查按钮是否存在”。
2. 当 MAIN 请求命令审批时，确认命令内容。
3. 需要持续运行的命令可以在右侧 Terminal 查看；任务结束后关闭对应 PTY，MAIN 会回收其子进程。
4. 对长输出，要求 MAIN 读取最新日志尾部并总结关键错误。
5. 完成后让 MAIN 给出验证结论。

## 结果确认

- 工具块显示已读取、搜索、运行或验证的目标。
- 命令工具返回 exit code、stdout、stderr、超时和输出截断信息；这些字段比自然语言“似乎成功”更可靠。
- 浏览器验证会说明检查目标和结果。
- 最终回复引用验证证据，而不是只说“应该可以”。

## 常见问题

**命令一直运行怎么办？**  
打开右侧 Terminal 查看状态。长驻服务应通过 PTY 观察；必要时关闭对应终端或停止当前 Run。超时的一次性命令会回收完整进程组，避免只杀父进程、留下子进程。

**MAIN 不能访问系统外文件怎么办？**  
MAIN 的项目工具通常受工作区范围限制。把需要分析的文件放入工作区，或通过附件/知识库导入。

**为什么包含变量、`cd` 或绝对路径的命令被拒绝？**
最终执行边界要求获批内容与真实执行内容一致，并会校验工作目录、可见 Shell 路径和重定向目标。把命令改成明确的工作区相对路径，或拆成多个可审查步骤。该校验不是 OS 级进程沙箱；一个获准的外部程序仍可能自行解释配置和内部 I/O，因此不要批准来源或影响范围不明的程序。

**浏览器验证失败怎么办？**  
确认 dev server 已启动、端口正确，页面没有登录或网络依赖阻塞。
