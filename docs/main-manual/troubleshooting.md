# 故障排查

遇到连接失败、工具失败或任务卡住时，先确认当前工作区、模型状态、审批状态和调试日志。

<!-- screenshot: docs/main-manual/assets/troubleshooting-debug-log.png -->

## 适用场景

- 模型无法连接或没有响应。
- MCP 扫描不到工具。
- 知识库导入或检索失败。
- 更新失败。
- 命令卡住或输出太长。

## 前置条件

- 已打开设置页。
- 可以访问 Debug Log。
- 能确认当前工作区和模型配置。

## 步骤

1. 先确认问题发生在哪一类能力：模型、工具、MCP、知识库、更新或命令。
2. 打开对应设置页，检查当前状态。
3. 使用测试连接、扫描工具或测试检索等内置检查入口。
4. 查看对话区工具块和右侧终端输出。
5. 打开 Debug Log，复制或导出最近错误。
6. 调整配置后，用只读任务重新验证。

## 常见问题处理

### 模型连接失败

1. 打开模型设置。
2. 确认 active profile 是 Local 还是 Cloud。
3. 本地模型检查服务是否启动、Endpoint 是否正确、模型是否已加载。
4. 云端模型检查协议、Endpoint、API Key、模型名和 API format。
5. 点击测试连接。
6. 如果任务运行中，等待运行结束后再切换模型配置。

### 模型回复说不能使用工具

1. 检查工具协议设置。
2. 对不支持 native tools 的服务切换到 XML。
3. 重新发送任务，并明确要求 MAIN 读取工作区文件。
4. 如果仍失败，导出 Debug Log。

### MCP 连接失败

1. 确认 MCP 服务器已启动。
2. 确认 URL 正确，尤其是是否需要 `/mcp`。
3. 点击测试连接查看诊断。
4. 点击扫描工具。
5. 确认外部工具或引擎当前会话已经连接。

### 知识库导入失败

1. 确认正在使用 MAIN 桌面应用。
2. 本地文件导入失败时，检查文件是否存在且可读取。
3. 网页导入失败时，检查 URL 是否需要登录或被限制访问。
4. 尝试减少递归深度或页面数量。
5. 导入后手动执行测试检索。

### 命令执行卡住

1. 打开右侧 Terminal。
2. 查看最近输出。
3. 如果是 dev server 等长驻命令，确认它是否已经正常启动。
4. 如果是测试或构建卡住，停止任务后让 MAIN 读取日志尾部并总结阻塞点。

### 更新失败

1. 打开 `Settings > About`。
2. 再次检查更新。
3. 如果仍失败，打开 GitHub Releases 页面手动下载。
4. 查看 Debug Log 中的更新相关错误。

## 结果确认

- 每个问题都应能定位到配置、网络、权限、工具协议或外部服务状态。
- 调整后用低风险任务验证。
- 无法解决时，导出 Debug Log，并保留当前模型、Endpoint 类型和出错步骤。

## 常见问题

**我应该先重启 MAIN 吗？**  
可以作为快速排查手段，但更建议先看设置页状态和 Debug Log，避免丢失当前任务线索。

**需要删除工作区里的文件吗？**  
通常不需要。除非你明确知道某些生成资产需要清理，例如 Game Studio 初始化资产。

**什么时候应该换模型？**  
当连接正常但工具协议、上下文长度或执行稳定性持续不满足任务时，可以换更兼容的模型。
