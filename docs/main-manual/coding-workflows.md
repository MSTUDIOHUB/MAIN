# 代码工作流

MAIN 可以在你的项目中阅读代码、定位问题、提出方案、修改文件并运行验证命令。

<!-- screenshot: docs/main-manual/assets/coding-workflow-diff.png -->

## 适用场景

- 修复报错或测试失败。
- 实现小功能或调整 UI。
- 重构局部模块。
- 让 MAIN 解释代码结构和风险。

## 前置条件

- 已打开项目工作区。
- 项目最好已经使用 Git。
- 已知道如何运行项目的测试、构建或 lint，或让 MAIN 先探索这些命令。

## 步骤

1. 切到 `工程实现` 场景。
2. 对简单任务使用 Fast 或 Chat，对复杂任务使用 Plan。
3. 描述目标、失败现象、相关文件或验收标准。
4. 让 MAIN 先读取相关文件和项目结构。
5. 当写入审批出现时，查看 Diff 后接受或拒绝。
6. 让 MAIN 运行测试、构建、lint 或项目特定验证命令。
7. 检查最终摘要和 Git Diff。

## 示例提示词

```text
请定位登录页按钮点击后没有响应的原因，先读相关组件和状态管理代码，再给出最小修复并运行相关测试。
```

```text
请把设置页里的模型连接错误提示整理得更清楚，要求不改变现有 API 行为，并验证 TypeScript 编译。
```

## 结果确认

- MAIN 说明它读取了哪些文件或搜索了哪些关键字。
- 文件改动通过 Diff 可见。
- 验证命令有明确输出。
- 最终回复包含改动摘要、验证结果和剩余风险。

## 常见问题

**MAIN 没有运行测试怎么办？**  
直接要求“请运行相关测试并修复失败”。如果项目没有测试，要求 MAIN 说明可替代验证方式。

**修改太大怎么办？**  
拒绝 Diff，并要求拆成更小步骤或先进入 Plan 模式。

**模型反复读同一个文件怎么办？**  
让 MAIN 基于已读上下文继续，或要求它总结当前阻塞点并采取一个具体动作。
