# 工作区与会话

工作区决定 MAIN 可以访问哪个项目；会话决定同一个工作区内的上下文和任务历史。

<!-- screenshot: docs/main-manual/assets/workspaces-sessions.png -->

## 适用场景

- 同时处理多个项目。
- 为不同任务保留不同对话历史。
- 在不需要项目文件时使用全局聊天。

## 前置条件

- 已配置模型。
- 已准备一个或多个本地文件夹。

## 步骤

1. 在左侧边栏添加工作区。
2. 选择项目文件夹。
3. 在工作区下创建新会话。
4. 给每个任务使用独立会话，例如“修复登录 bug”和“整理发布说明”分开。
5. 需要临时问答时进入全局聊天。
6. 不再需要的会话可以从侧边栏删除。
7. 如果工作区列表太长，可以折叠不常用项目。

## 结果确认

- 每个工作区有独立会话列表。
- 切换会话后，中间对话区恢复对应上下文。
- 当前工作区会影响文件面板、终端命令和 Git 状态。
- 全局聊天不会默认读取某个项目文件夹。

## 常见问题

**删除会话会删除项目文件吗？**  
不会。删除会话只影响 MAIN 的对话记录，不会删除工作区源文件。

**一个会话可以跨工作区使用吗？**  
不建议。工作区会话绑定项目上下文，跨项目任务应新建会话。

**为什么有些旧会话标题看起来被自动生成？**  
MAIN 会根据任务内容生成标题，方便在侧边栏快速识别。
