# 上下文与记忆

MAIN 会在模型上下文有限的前提下管理会话历史、项目资料、工具结果和知识库检索，让长任务尽量保持连续。

<!-- screenshot: docs/main-manual/assets/context-settings.png -->

## 适用场景

- 长对话后模型开始忘记前文。
- 本地模型显存紧张，需要调小上下文。
- 想让 MAIN 引用资料，但不想把全文塞进提示词。

## 前置条件

- 已配置模型。
- 如需使用知识库，已在知识库面板创建并启用知识库。

## 关键概念

上下文窗口是模型一次请求能看到的信息上限。MAIN 会把当前任务、会话摘要、项目上下文、工具结果和必要说明放入其中。

压缩阈值控制 MAIN 什么时候更早整理历史。较低阈值节省显存，较高阈值保留更多对话和工具结果。

会话记录用于恢复历史会话。关闭会话记录后，MAIN 会减少持久化内容，但也会影响你回看和继续旧会话。

知识库采用按需检索。启用的知识库不会把全文直接塞进上下文，而是在发送任务时根据问题搜索相关片段。

## 步骤

1. 进入 `Settings > Context`。
2. 根据模型和设备内存调整上下文上限或压缩触发阈值。
3. 如果本地模型变慢或报错，优先降低上下文设置。
4. 需要长期资料时，进入知识库面板导入文件或网页。
5. 启用相关知识库，再发送需要引用资料的任务。

## 结果确认

- 设置页会显示当前 token 上限和预估显存占用。
- 长任务中 MAIN 会尽量保留近期关键工具结果。
- 知识库命中时，工具记录会显示搜索和摘录行为。

## 常见问题

**上下文越大越好吗？**  
不一定。更大的上下文会消耗更多显存和时间。对于本地模型，稳定性通常比极限长度更重要。

**知识库能替代工作区文件读取吗？**  
不能完全替代。知识库适合资料和参考文档；工作区文件读取适合当前项目的真实源码和状态。

**为什么 MAIN 会压缩历史？**  
为了在模型上下文有限时继续任务。压缩会保留关键结论，但不等于完整逐字记录。
