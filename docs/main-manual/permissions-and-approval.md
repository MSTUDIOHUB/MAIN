# 权限与审批

MAIN 会把高风险操作放到你面前审查，让你决定是否允许文件写入、替换、命令执行或浏览器控制。即使用户允许，Rust 仍会在执行前做最终路径、命令、网络与进程安全校验。

## 适用场景

- 担心 AI 误改文件。
- 需要查看 Diff 后再接受修改。
- 希望了解什么时候可以开启自动批准。

## 前置条件

- 已打开工作区。
- 当前任务涉及写入、命令或其他敏感工具。

## 审批类型

文件写入和局部替换会显示 ActionCard。你可以查看目标文件和 Diff，再选择接受或拒绝。

命令执行会要求确认，尤其是会写入项目、启动长任务或影响系统状态的命令。

Plan 模式会先要求批准计划。批准后，MAIN 才会按计划执行后续写入和验证。

自动批准适合你信任当前任务、当前工作区和当前模型时使用。开启后仍建议观察工具记录和最终 Diff。

自动批准只减少重复确认，不会放开 MAIN 能检查到的工作区外路径、危险 Shell 结构、metadata 网络地址、失效审批或其他硬安全边界。

这些校验不是操作系统沙箱。MAIN 会约束自己的文件 API、命令工作目录、Shell 重定向和 HTTP 代理请求，但一个已经获准启动的外部程序仍可能按照自己的参数或配置访问其他资源；高风险可执行程序仍需人工审查。

## 步骤

1. 当审批卡片出现时，先阅读操作目标。
2. 如果是文件修改，打开 Diff 预览。
3. 如果是命令，确认命令意图和工作区范围。
4. 点击接受以继续，或点击拒绝让 MAIN 改方案。
5. 对重复低风险操作，可以在当前会话中开启自动批准。

## 结果确认

- 接受后，工具状态会从等待变成已执行。
- 拒绝后，MAIN 应停止该操作并根据你的反馈调整。
- Rust 最终校验拒绝时，该工具会留下结构化受阻/失败证据；MAIN 会换方案或形成明确结论，不会把 Turn 留在永久执行中。
- 文件变更可以在右侧 Diff 查看。
- 命令输出可以在终端或工具块查看。

## 常见问题

**拒绝一次操作会结束整个任务吗？**  
不一定。MAIN 可能会根据拒绝结果寻找替代方案，或询问你如何继续。

**自动批准是否适合所有任务？**  
不适合。涉及删除、发布、提交、迁移、安装依赖或访问外部服务时，建议保留人工审批。

**只读工具为什么不审批？**  
只读工具不会修改项目，通常需要自动执行才能让 MAIN 快速获得上下文。

**我已经批准，为什么命令仍被拒绝？**
审批代表你的授权，不代表任意字符串都安全。命令替换、变量展开、嵌套 shell、路径逃逸或危险重定向仍会被 Rust 最终边界拒绝。
