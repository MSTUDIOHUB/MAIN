# 权限与审批

MAIN 会把高风险操作放到你面前审查，让你决定是否允许文件写入、替换、命令执行或浏览器控制。

<!-- screenshot: docs/main-manual/assets/permissions-action-card.png -->

## 适用场景

- 担心 AI 误改文件。
- 需要查看 Diff 后再接受修改。
- 希望了解什么时候可以开启自动批准。

## 前置条件

- 已打开工作区。
- 当前任务涉及写入、命令或其他敏感工具。

## 审批类型

文件写入和局部替换会显示 ActionCard。你可以查看目标文件和 Diff，再选择接受或拒绝。

命令执行会要求确认，尤其是会写入项目、启动长任务或影响系统状态的命令。

Plan 模式会先要求批准计划。批准后，MAIN 才会按计划执行后续写入和验证。

自动批准适合你信任当前任务、当前工作区和当前模型时使用。开启后仍建议观察工具记录和最终 Diff。

## 步骤

1. 当审批卡片出现时，先阅读操作目标。
2. 如果是文件修改，打开 Diff 预览。
3. 如果是命令，确认命令意图和工作区范围。
4. 点击接受以继续，或点击拒绝让 MAIN 改方案。
5. 对重复低风险操作，可以在当前会话中开启自动批准。

## 结果确认

- 接受后，工具状态会从等待变成已执行。
- 拒绝后，MAIN 应停止该操作并根据你的反馈调整。
- 文件变更可以在右侧 Diff 查看。
- 命令输出可以在终端或工具块查看。

## 常见问题

**拒绝一次操作会结束整个任务吗？**  
不一定。MAIN 可能会根据拒绝结果寻找替代方案，或询问你如何继续。

**自动批准是否适合所有任务？**  
不适合。涉及删除、发布、提交、迁移、安装依赖或访问外部服务时，建议保留人工审批。

**只读工具为什么不审批？**  
只读工具不会修改项目，通常需要自动执行才能让 MAIN 快速获得上下文。
