# 技能与协议包

技能和协议包让 MAIN 在特定项目或工作流中加载额外说明、命令文档、工具定义和模板。

<!-- screenshot: docs/main-manual/assets/skills-modal.png -->

## 适用场景

- 给 MAIN 增加团队编码规范或项目约定。
- 为某类任务提供固定流程。
- 导入一组协议、模板、命令和专家说明。

## 前置条件

- 已打开 MAIN。
- 如需让技能只作用于某个项目，先打开对应工作区。
- 导入协议包前，确认来源可信。

## 技能类型

提示词技能会把额外说明加入 MAIN 的系统提示词，用于约束风格、流程或标准。

工具型技能会暴露函数 schema。实际执行需要对应后端能力、内置工具或 MCP 工具支持。

协议包通常是更完整的工作流包，可能包含 `SKILL.md`、命令文档、模板、规则和其他资源。

## 步骤

1. 打开 Skills 面板。
2. 新建技能，填写名称、描述和内容。
3. 根据用途选择提示词、工具或协议包类型。
4. 启用或停用技能。
5. 导入协议包时，把 ZIP 拖入或选择文件。
6. 回到会话，发送匹配技能用途的任务。

## 结果确认

- Skills 列表显示技能名称和启用状态。
- 启用的提示词技能会影响后续回答和执行方式。
- 协议包文件会被解压到当前工作区的协议目录。
- Game Studio 等场景会按需读取协议包中的命令和模板。

## 常见问题

**技能越多越好吗？**  
不是。只启用当前任务需要的技能，避免提示词冲突和上下文膨胀。

**工具型技能为什么不能执行？**  
schema 只是告诉模型有一个工具形状。真正执行还需要后端处理器、内置工具或 MCP 服务支持。

**协议包会污染所有项目吗？**  
协议包通常按工作区作用。切换工作区后，需要在新工作区单独初始化或导入。
